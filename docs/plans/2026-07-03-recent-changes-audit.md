## Architecture summary

- **Entry points:** Next.js 16 App Router pages → `hooks/` (React Query) →
  `fn/` server actions (`ActionResult<T>`) → `data-access/` (auth guards) →
  Drizzle/Postgres. Registry side: `fn/certification/submit-removal.ts` →
  `lib/isometric/` client.
- **Core data flow (submission):** `loadRemovalSubmissionContext`
  (`certify-context-core.ts`, 962 lines — full DB graph + live registry reads) →
  `submitRemoval` (`submit-removal.ts`, 955 lines, ~22 inline guards) →
  `INPUT_MAPPING` datapoint transform + `weightedBatchChemistry` overlay →
  submission-ledger claim (pure `decideSubmissionClaim`) → registry POSTs with
  reconcile-on-retry.
- **What the 3 days changed:** samples re-anchored on credit batches (#332),
  server-derived tier + per-lineage window guard (#347), credit-batch aggregates
  derived on read (#344), real→numeric for credit-bearing columns (#342),
  1000-year durability path (#341), diesel via `fuel_usage_by_volume` (#339),
  `completed_on` anchored to application date (#340), canonical UTC readings CSV
  import (#321/#323), project-emissions journal removed (#324/ADR 0018).
- **Depth verdict:** the pure calculation layer (`lib/calculations/*`), the
  window enforcement (3 intentional layers), the submission-claim choreography,
  and the readings CSV parser are genuinely deep and tested. The shallow spots
  are the **sample-intake invariants** (scattered over 5 layers), the
  **submit-preflight guard wall** (inline, mirrored by hand into readiness), the
  **template-binding vocabulary** (encoded 3×), and the **SQL-aggregate numeric
  coercion** (124 per-call-site `Number()`s across 19 files).

## Findings by severity

Counts after dedupe + verification: **2 high** (clusters), **7 medium**,
**5 low**, 1 rejected. No criticals — nothing found that corrupts credit-bearing
figures on the current staging path; the submit-time durability gates fail
closed in every scenario below.

### HIGH

**H1 — `samples.sample_code` uniqueness is not DB-enforced; every guard around
it is racy or dead.** *(flagged independently by 3 agents)*
`src/db/schema/production.ts:171` has no `.unique()`. The duplicate pre-checks
run on `db` *before* the write transaction opens
(`src/data-access/samples.ts:543-550`, `:682-691`), and `withAutoCode`'s
collision retry only fires on a PG 23505 whose constraint name matches
`_sample_code_unique` — a constraint that does not exist
(`src/data-access/code-generator.ts:96-106`), so the retry is dead code for this
table. Two concurrent creates (or a two-tab double submit; the form lock is
per-tab) mint the same `SAM-…` code — and a true double-submit duplicates a
chemistry replicate, inflating the ≥3-replicates gate and the mass-weighted
batch chemistry.
**Fix:** new migration adding a unique index on `sample_code` (scope to match
`generateNextSampleCode`'s tenancy — codes look global today), map 23505 via the
existing helper, delete the two pre-checks. The `withAutoCode` retry then works
as designed with zero further change.

**H2 — the 1000-year tier/evidence invariant is one-directional, racy, and
implemented three times.** *(flagged independently by 3 agents)*
- `requireBatchTierEvidence` reads the batch tier with a plain SELECT
  (`src/data-access/samples.ts:467-470`); its header comment claims the
  transaction prevents a concurrent tier promotion — it does not (READ
  COMMITTED, no lock; commit `a164808` moved the check in-tx but the race
  stands). Verified.
- Batch-side writes bypass the guard entirely: `updateCreditBatch` copies
  `durabilityOption` straight into the update with no member-sample check
  (`src/data-access/credit-batches.ts:467-468` — verified), create back-fills
  samples (`:403-407`), membership edits re-point samples (`:619-632`).
- `updateSample` validates the merged state against an `existing` row read
  *before* the transaction with no `FOR UPDATE`
  (`src/data-access/samples.ts:672-675` vs tx at `:746`) — two concurrent
  partial updates can null both TGA fields on a 1000-year batch (write-skew).
- The same R₀/TGA rule also lives in the client form
  (`sample-form.tsx:168-174`) and a zod `superRefine` over the client's tier
  mirror (`schemas/samples.ts:160-178`) — the stale-mirror pattern #347 was
  written to eliminate survives as parallel enforcement.
Damage is bounded (submit-time durability gates fail closed), so this is a
data-entry-integrity issue, not a credit-issuance bug.
**Fix cluster:** (a) `.for("share")` on the batch read in
`requireBatchTierEvidence` + move `updateSample`'s existing-read in-tx with
`.for("update")`; (b) validate (or block) batch-side tier flips against member
samples; (c) make `requireBatchTierEvidence` the sole enforcer — demote the zod
and client mirrors to display-only; (d) correct the overclaiming comment.

### MEDIUM

**M1 — #344's derived aggregates are never re-read after the mutations that
move them.** Application create/update/delete invalidate only
`applicationKeys.*` — never `creditBatchKeys`
(`src/hooks/use-applications.ts:92-136`; verified no `creditBatch` reference in
the file). With `refetchOnWindowFocus: false` (`src/app/providers.tsx:14-15`), a
mounted credit-batch view shows the pre-mutation applied-weight/CO₂e until
remount — the staleness #344 eliminated server-side, reintroduced at the cache
seam. **Fix:** invalidate `creditBatchKeys.lists()` + affected details in those
three mutations (a lineage walk isn't needed; broad invalidation is fine at this
scale).

**M2 — `submitRemoval` snapshot TOCTOU: the in-lock re-resolution covers source
IDs only.** Chemistry, run set, applied masses, and the #340/#347 window guards
are all derived from `ctx` read before the evidence-ledger HTTP round-trips;
the claim's in-lock re-check (`submit-removal.ts:589-622`) re-resolves only
`sourceIds`. A concurrent sample/application edit lands inside a
now-locked lineage but is absent from the submitted snapshot. Mitigated by
supersede-on-hash-change at re-submit. **Fix direction (design, not mechanical):
compute a lineage fingerprint (counts + max `updatedAt` over
samples/applications/runs) in `resolve` and return `blocked/state-changed` on
drift — or take the artifact lock before building ctx. Never widen a DB lock
around the HTTP calls.**

**M3 — `deleteCreditBatch` leaves anchored samples in a contradictory state and
trips a legacy FK.** (a) It nulls `samples.creditBatchId`
(`credit-batches.ts:665-668`); tier then falls back to R₀-presence inference
(`samples.ts:279-285`, `:421-424`), so a 200-year batch's samples with
incidental R₀ silently re-count as 1000-year in stats/readiness — a state the
app can no longer create. (b) Legacy `credit_batch_applications` rows (NO
ACTION FK) make pre-re-grain batches undeletable via a raw 23503 that isn't
mapped to a `SafeError`. **Fix:** domain decision — block delete while samples
reference the batch (mirror of the run-membership posture) or require an
explicit re-anchor step; sweep or drop the vestigial `credit_batch_applications`
table.

**M4 — readings import: duplicate telemetry under concurrency; stranded doc on
failure.** (a) `replaceProductionRunReadingsInWindow` is transactional but two
*concurrent* imports interleave (T2's range-DELETE can't see T1's in-flight
INSERTs) and there's no unique `(production_run_id, timestamp)` — doubled 5-min
readings would ride into the Isometric sensor submission
(`data-access/production-run-reading-imports.ts:87-110`,
`db/schema/production.ts:145`). (b) A failed import leaves the uploaded
`sensor_data` document listed exactly like a successful one, with no re-import
affordance; the only recovery is delete + re-upload, undocumented
(`production-readings-documents.tsx:55-75`). **Fix:** `uniqueIndex` +
`onConflictDoUpdate` (or per-run advisory lock); add a per-file "Import
readings" retry action or persist import status on the document row.

**M5 — cohort picker renders fetch failure as a false "no runs in window" empty
state.** The form destructures only `data`/`isSuccess`
(`credit-batch-form.tsx:279-296`); on error the options fall back to `[]` and
`CohortPickerSection` asserts "No production runs fall within this production
window." — no error state, no retry. The #343 gate correctly prevents the *data
wipe*; the UI still lies about *why* the list is empty. **Fix:** destructure
`isError`, render a distinct error state and suppress `noMatchMessage`.

**M6 — Zod ⇄ numeric-ceiling divergence on converted columns.**
`hToCOrgRatio`/`oToCOrgRatio` are `numeric(7,6)` (ceiling 9.999999,
`numeric-families.ts:29-31`) while their zod fields are unbounded
(`schemas/samples.ts:115-116`, `:258-259`); wrong-scale entry (70 for 0.70) now
becomes a PG 22003 overflow surfaced as a generic sanitized error
(`db/errors.ts` maps only 23505). The unmerged branch
`fix/mass-input-max-caps` (PR #345) covers the *mass* fields — the ratio/percent
fields still need caps. **Fix:** merge #345, then add matching `.max()` caps for
ratio fields (values are domain decisions).

**M7 — #339 requires an Isometric template re-author before the live flip.**
Diesel now submits as `pyrolysis / fuel_usage_by_volume / volume_of_fuel`
(litres) and needs the volumetric diesel EF bound as a template fixed input
(`transformers/datapoint.ts:148-156`). Both drift directions fail closed and the
sequencing is recorded in `docs/isometric/changes.md` — this is a pending
external coordination step, tracked here so it isn't lost.

## Architecture: deepening candidates (from `/improve-codebase-architecture`)

The explorers confirmed several modules as genuinely deep — leave them alone:
`lib/calculations/*` (pure, gap-contract results), the readings CSV parser
(`lib/production-readings/readings-csv.ts` — the model to replicate), the
window 3-layer defense, `claimSubmissionDraft` choreography,
`credit-batch-previews.ts` (passes the deletion test), `registry-create.ts`.

### Strong

- **A1 — single removal-submission preflight gate.** `submitRemoval` carries
  ~22 inline `SafeError` throws (`submit-removal.ts:299-442`); only the
  durability gate follows the good pattern (one pure evaluator feeds *both*
  readiness and submit, so they can't disagree). Generalize: pure
  `evaluateRemovalBlockers(ctx): RemovalBlocker[]` covering window/template/
  transport/lineage/durability; submit throws once on non-empty; readiness reads
  the identical list. Makes #340/#347-class rules one-edit and turns guard
  sequencing into a table test (today it needs a 5-module mock harness;
  `certify-context-core.ts` has **no test file**).
- **A2 — one canonical template-binding registry.** The (group, blueprint,
  input) vocabulary is encoded three times: `INPUT_MAPPING`
  (`transformers/datapoint.ts:35-174`), `certify-field-registry.ts:88-117`, and
  `certify-context-core.ts:112-116` (which carries a literal "keep in sync"
  comment). #339 rippled through all three. One tuple-keyed table; the others
  become projections; `MAPPING_REVISION` then hashes the true single source.
- **A3 — typed numeric-aggregate helpers.** 58 `sql<number>` fragments whose
  `number` annotation is a lie (pg returns strings for SUM/AVG), patched by 124
  per-call-site `Number()`s across 19 data-access files; `.mapWith(Number)`
  already proves the fix in exactly 3 places. Add `sumNumeric()`/`avgNumeric()`/
  `countRows()` helpers next to `numeric-families.ts` — coercion becomes
  correct-by-construction and the `debc2ff` bug class (silent empty-bin
  mislabel) dies.
- **A4 — `StorageProvider.getObject` seam.** The interface stops at
  `createDownloadUrl`, so ≥3 server callers re-implement presign → self-HTTP →
  ok-check (`fn/production-run-reading-imports.ts:84-92`,
  `fn/certification/sources-transfer.ts:46-65`, `submit-telemetry.ts:536`).
  Fails the deletion test. Add `getObject/getObjectText`; L3's timeout gets one
  home; the import fn becomes testable via the existing test-provider hook.
- **A5 — dead-code deletions.** (a) The manual add-reading chain
  (`fn/production-runs.ts:346`, `data-access/production-runs/readings.ts:41`,
  `hooks/use-production-runs.ts:479`, `schemas/production-runs.ts:247`) has zero
  component consumers and contradicts the shipped "CSV-import-only" invariant —
  keep the DB `gasFlowRate` column (legacy rows; `submit-telemetry.ts` reads
  it). (b) `checkCreditBatchDateOverlap` (`credit-batches.ts:772-800`) — zero
  callers (verified) *and* it encodes a per-facility no-overlap rule that
  contradicts ADR 0016's concurrent-batches model; delete, or re-scope to
  (facility, feedstock) if ever wired.
- **A6 — sample-intake consolidation** = H2(c) above: one authoritative
  enforcer module for tier/evidence at intake; also the natural home for the
  currently-unenforced "samplingTime within the batch window" check.
- **A7 — test + thin the preview composition seam.** Extract the pure
  per-application assembly from `credit-batch-previews.ts:146-175` into
  `biochar-removal.ts` and unit-test the 200/1000 gap contract without DB.

## Sequenced remediation strategy

Each phase is independently shippable; order keeps diffs bisectable and puts
integrity ahead of refactors.

1. **Phase 0 — mechanical quick wins (single small PR).**
   L1 (SafeError in code-generator), L4 (param rename), comment corrections
   (H2's overclaiming guard comment, `assertCanMutateCertifiedLineage` empty-
   lineage caveat), A5 deletions (`checkCreditBatchDateOverlap`, manual
   add-reading chain).
2. **Phase 1 — integrity backstops (one PR per item).**
   H1 unique index migration + pre-check removal; H2(a)(b) lock fixes +
   batch-side tier-flip validation; M4(a) readings `uniqueIndex` +
   `onConflictDoUpdate`; M1 mutation invalidations.
3. **Phase 2 — error surfaces + validation caps.**
   M5 cohort-picker error state; M4(b) re-import affordance; L2 retry button;
   M6 ratio caps (after PR #345 merges — coordinate).
4. **Phase 3 — architecture deepening (one PR each, in this order).**
   A3 aggregate helpers (mechanical, high leverage) → A1 preflight gate (+ B2,
   B3 as natural companions) → A2 binding registry → A4 storage seam (+ L3
   timeout) → A7 preview-seam extraction + missing pure-module tests → B1
   chemistry owner.
5. **Phase 4 — decisions + docs (needs product/domain input).**
   M3 delete-path posture (block vs re-anchor — good `/grill-me` candidate);
   M2 lineage-fingerprint design; M7 template re-author scheduling; B9
   CONTEXT.md updates; move accepted L5 residue into `docs/open-questions.md`
   entries where not already there.
