# Design decisions

This is the per-surface log of what we tried, what replaced it, and why. Read it before proposing a layout or pattern on a surface; never re-propose something listed under "Rejected". Add an entry when a pick or a reversal lands (date, what was tried, what replaced it, the issue or PR). The rules themselves live in `docs/design-system.md`, `docs/forms.md` and `docs/ux-writing.md`; this file holds the history.

## Cross-cutting

- **Casing** (#546, #848, #868; 2026-07-27 to 09-30): Title Case chrome and mono caps table headers → sentence case everywhere. Mono stays for the `PageHeader` eyebrow, codes and IDs; `.label-button` renders buttons in mono caps from sentence-case source text. Why: a half-converted family reads as drift ("consistency is king").
- **Simple and Detailed** (#821/#822 → #847; 2026-09-21 to 09-29; #1249; 2026-10-20, Kenji): Simple hid derived blocks and some inputs → both modes show the same information, Detailed adds explanation only → the switch is removed. Explanations open from an (i) on hover and on tap; two short lines stay inline (the dry mass formula under a moisture split, the dry biochar before → after line on a stock movement); inline text is otherwise for error messages. Rejected: any "Add X" reveal or hidden step in Simple; everything behind an (i) with no inline line (A); in-place "Show calculation" rows (C).
- **Certification marker** (#851 → #858, #1117; 2026-09-30, 10-16): seal glyph and a sheet legend → "CERT" text chip, no legend. A requiredness legend was rebuilt in #1117 and closed unmerged. Rejected: "Required for certification" text.
- **Typography layering** (#822; 2026-09-21 to 09-23): a layered typography import switched on unreviewed utilities app-wide → reverted; only `.font-medium` is overridden.
- **Stat card scope** (#690, #1279; 2026-10-20): "on this page" sums became whole-facility server totals; a failed stats load shows "Could not load" instead of 0. Rejected: page-scoped figures. #690 part 3 extends it to Facilities, Reactors, Suppliers and Formulations: the cards keep the archived toggle (Facilities, Suppliers, Formulations) or the working facility (Reactors) as their one scope, ignore search and paging, and Facilities keeps three cards (Active/Archived facilities, Total reactors, Wet feedstock on hand with the storage-bin count as its description), all across every facility matching the archived toggle. Toggle-scoped count cards carry no description that only restates the title (#1347; 2026-10-21).
- **List-page subtitle** (#1245; 2026-10-20): "every list page gets a subtitle" → a subtitle stays only when it adds information the title lacks. Why: a subtitle that restates the title ("Orders" / "Manage your orders") is filler.
- **Form subgrid** (2026-07-24): `.grid > .form-field` subgrid → reverted; shorten labels instead.
- **Dialog actions** (#1150; 2026-10-17): right-aligned footers → bottom left, primary first, secondary after; refused delete is a dialog with "Archive instead" first.
- **Override controls** (#1123; 2026-10-16 to 10-18): the user asked for the override inside the input → reverted the next day ("it sucks what i proposed"): a secondary outline button next to the input, labelled "Reset to default"; "Refresh from location" is a compact action below the input that opens a dialog showing old → new.
- **Missing mass figure** (#1251; 2026-10-20, Kenji): two full-size "Not recorded" figures in the Biochar output stat card collided at 1440 px → each missing `MassPair` figure is small grey regular text with `data-empty`, both labels kept. Rejected: collapsing the pair into one line.
- **Where you are** (settings cleanup #1277; 2026-10-20, Kenji): the sidebar showed the organization name only for multi-org users, a switch dropped you on the dashboard with no word, and a Platform Admin inside an organization looked like its member → the sidebar header always shows the organization name with a membership role chip ("Owner", "Admin", "Member"), the switcher opens only when there is another organization to go to, a switch ends with the toast "Now working in <org>.", and a Platform Admin without a membership sees a bar above every page ("Platform Admin in <org>", "Back to Platform"; dark purple ink, the app chrome colour, not an area accent). The chip is for membership roles only: the bar already says "Platform Admin", so that state gets no chip, and a Platform Admin who is also a member keeps the membership chip and sees no bar. The sidebar section "Admin" is now "Platform"; on `/admin/organizations` the row button "Enter" is "Open" and the organization you are in carries plain "Current" text instead of a button (neutral, so it does not read as a health chip). If another tab switches organization, this tab shows no chip, bar or Current claim and reloads once. Why: acting inside someone else's organization has to be visible, and "workspace" is not a glossary word. Rejected: a bar for members, a bar for a Platform Admin who is also a member, and a "Platform Admin" chip next to the bar.
- **Facility column on scoped lists** (#690 part 4, PR #1354; 2026-10-21, Kenji; removed 2026-10-22, Kenji's question "we dont need the facility column at all?"): Orders, Production Runs, Biochar Products and Reactors repeated the facility on every row although the facility switcher scopes them to exactly one facility (no all-facilities mode) → part 4 hid the column by default; part 5 deletes it from these four lists, so it is not in the Columns menu either. Row data still carries `facilityId` and `facilityName`. Production Runs keeps about 15 px of sideways scroll at a 1130 px window. Rejected: hiding a second column, and narrowing the actions column on every table.
- **Columns control** (#690 for the rule; 2026-10-22, Kenji for removing Facility): a Columns control offers fields that start hidden, or it is not shown. Added as hidden-by-default columns from the row payload only, no new joins: Applications (Delivery, Crop type, Field identifier), Biochar Products (Water added, Density), Orders (Customer location, Formulation, Packaging), Deliveries (Customer location, Driver, Vehicle, One-way distance, Distance source), Customers (Address, Contact email, Contact phone), Feedstock types (Description), Feedstocks (Vehicle, One-way distance, Notes), Production Runs (Operator, Biochar moisture, Residence time, Electricity, Startup / plant diesel, Genset diesel), Reactors (Nominal throughput), Samples (Lab name, Analysis date, O:C org ratio, Moisture, pH, Ash content), Suppliers (Source region, Address), Removals (Reporting start, Reporting end; they repeat the window under the Removal code on purpose, because as columns they sort by start or by end). Fields that start hidden stay out of the client-side search on Feedstock types and Removals (`enableGlobalFilter: false`). Control removed: Formulations (every field is already a column) and GHG Statements (nothing to add). Dropped: Applications "Stored CO2e" (the column is never written; the real figure is the credit batch preview) and Biochar Products "Status" (no operator can set or see it). The open menu sits on the popover layer, so a sticky actions column no longer paints over it. Column headers use the record's detail sheet label (Samples "Lab name", Deliveries "Customer location" as on Orders, Applications "Delivery"), and long free text stays on one line with an ellipsis. Rejected: hiding Facility by default (part 4's first approach, a column that is never useful), and keeping a Columns control that can only subtract.
- **Value changes** (2026-09): sentences describing a change → two blocks with an arrow (before → after); unchanged readings ("30% → 30%") are not shown.
- **Busy until the result shows** (#1345; 2026-10-21): buttons went idle when the request returned, so Allow on the consent page looked dead for seconds before the browser left for claude.ai → the button stays busy through the navigation and only a failure clears it (rule under Button in `docs/design-system.md`). Applies to consent, the organization picker, sign-in, invitation accept and create, organization switching in the sidebar and on Platform, and the setup guide steps.

Each pane keeps a scope line, its caption and the who-can-change footnote; phones get one grouped select instead of the rail. - **Profile** (#1277 wave 2; 2026-10-22, Kenji): there was nowhere to change your own name or password → Settings, You, Profile, the first pane under You for everyone (Platform Admins included): the name saves on its own ("Save name"), the email is shown as text with one line that an Admin invites a new address, and "Change password" asks for the current password, then signs out every other device while this one stays signed in. Why: decisions 3 and 4 on the round 2 answers page. Rejected: changing the email in place (a confirmation mail flow for a rare case), a "Sign out other devices" box, keeping other devices signed in.

- **Section headings** (#995): "Required information", "Additional information" → removed; section titles are optional, and read views follow the form.
- **Stock entries**: a "Correct entry" action on stock movements → rejected; correct the source form or use a named correction.
- **Production run status** (#991): Draft and Running on create → create as Running or Complete; Cancelled is an action.
- **Refused saves** (#1298; 2026-10-20): one bottom line, delivery all-or-nothing → each reason at the field it names, the rest at the bottom. A lock shows "Locked" at each changed field with the reason once; the summary says "Not saved. 1 field is locked.", not "Fix". Whole-record locks stay at the bottom. Locks are not re-read after a refusal (#1327). 2026-10-21 look pass: one box, names-only links, title/detail split, full-width field messages.
- **Choice controls** (form cleanup, 2026-09-29): selector text → choice cards when the choice has a consequence, segmented controls for short equal options, selects for the rest.

## OAuth consent

- **Reconnect after a claude.ai Disconnect** (Q104, round 15, #1330; 2026-10-21): a stored consent showed the board alone with every allowed area locked and resubmitted, so the person could never narrow → any connect that is not a step-up shows the three first-connect choices (default Read only), nothing locked, and Allow replaces the stored consent with what is ticked. A step-up (a live refusal hint) keeps the board with the allowed areas locked and the refused write marked New. Why: claude.ai sends no revoke on Disconnect. Two refinements: the authorize hook adds `prompt=consent` on every client authorize entry, so the page shows on every connect, even when the stored consent already covers the request; and the choices start from the stored consent (Read only when the stored consent is exactly the requested reads, Read and write when it is exactly every requested read and write, otherwise Choose per area with the stored scopes ticked; a first connect starts at Read only). Why: the page now appears on routine re-authorizations, and a quick Allow must never add or drop anything. Rejected: unticking allowed areas on the locked board, and always starting at Read only.

## Stock, bins and transport

- **Stock blocks** (PR 822 picks, #1001; 2026-09-23, 10-17): dry biochar headline → wet mass first, dry biochar below in a smaller, lighter line; correction previews show wet first.
- **Stock history**: timeline. Bin history (#1004): always wet mass, dry when available, the rest in the table, top to bottom on phones. Wet mass and water estimates read in whole kg; the exception (#1349, 2026-10-21) is a change whole kg would hide (2 kg wet at 10% moisture takes 0.2 kg of water): the Change and After figures of that row, and the Wet mass total, show the first precision that keeps it visible (one decimal, then the three decimals a mass is stored at), so the row adds up and never reads "-0".
- **Stock history, late entries** (#1300, 2026-10-22): a run entered after a draw used to leave the history frozen, so the day end and the chart could end away from the bin card. Past wet changes now recompute from the bin's current layers, so the history always ends where the card does. The saved figure stays on the row, in its details, as "Saved change: Wet mass +10 kg. Re-estimated with the entries known now." after "Recorded", shown only when its rendered figure differs from the current change. No cause is named, since the code cannot know whether a later entry, a back-dated entry or a moisture rule moved it. The (i) reads "A later entry never changes what an earlier one measured; wet estimates update." Rejected: freezing the history and letting it drift from the card.
- **Bin sheet** (#992): titled cards, the bin figure is hoverable, one text action top right per card, ⓘ next to the title, one "Adjust stock" (lost mass) action. Rejected: "Record loss" and "Reconcile stock" buttons; stock history buttons outside the bin route.
- **Lost mass wetter than the bin** (#1252; 2026-10-21): variant A (re-estimate) picked over B (refuse until a count). A removal measured wetter than the bin's estimate is saved, and only when wet mass would otherwise fall below dry biochar does what stays get re-estimated at the removal's moisture, until the next count. One warning notice with one action, "Edit the moisture" (focuses the field). Wording picked on a mock (framing C, 2026-10-21): the title asks to check the moisture against the bin's own ("Check the moisture: 50% against the bin's 20%"), one body line says what saving does ("If 50% is right, saving changes the bin until it is counted again"), a Bin now to After saving pair shows the wet figures, and the arithmetic sits behind the (i) "Why the bin goes up". The words "estimate", "re-estimates" and "next count" stay out of the notice and the mass flow labels. A sub-bin is named instead of the bin; differing readings title it "Check the moisture readings" with one pair per sub-bin. The mass flow diagram opens from the (i), under the "Why the bin goes up" text (Kenji, before merge: "show the sankey graph on hover of the info icon"), not under the notice. The bin card says where the moisture came from: "Moisture estimated from the <lost mass | delivery> of <date>". Deliveries drawn wetter than the bin get the same notice. Rejected: two actions that sound alike ("check the moisture" and "record a moisture reading"), a blocked save.
- **Transport legs** (#892): derived transport on every record → transport only where goods move; route rail variant B, one line per leg with a menu, "View map" in a dialog. Rejected: two competing summary areas on the right.
- **Distance refresh action** (#1262; Kenji, 2026-10-20): the outlined uppercase "Refresh from location" button was "huge" → "text only with underline and a refresh icon before, so it fits into the row". The edit row and the read-view notice both use it. Rejected: the boxed button on the hint line.
- **Production run flow** (#888, #999): Sankey, left to right, with numbers; water taken up shown as an inflow.
- **Energy → Emissions** (2026-10-01 → #1140): toggled explorer (variant F) was "too complicated" → list and Sankey toggle (G) → replaced by Emissions: overview C, detail C3c (monthly ledger, whole row clickable, ⋮ menu), then accordion layout E (full width, line description above Source, comment as an action). Rejected: a "Nothing to record" button; default reads "Nothing recorded" with a quiet "Add manual entry".

## Removals

- **Empty components in New Removal** (epic #1058 PR 4, round 7; 2026-10-20, Kenji): empty template components confirmed on the submit step (A) or inside the compact batch boxes of selection (C, #1202) → version B, its own "Empty components" step between selection and Confirm & submit. One card per credit batch, "Add entry" per component (new tab), one optional note and "Record n components as zero", "Recorded zero" once confirmed, Undo on this step only. The step is skipped when nothing is empty; Continue refuses with a reason that names the components and batches; the submit step shows a read-only "Components sent" (value, source, files). Copy says "component", never "line" (2026-10-20). Rejected: confirming on the submit step, and the confirmation inside the selection boxes.

- **Submit step: one table** (2026-10-22, Kenji picked variant A "One table" over B "By credit batch" and C "Summary first"): the step showed the same facts in Summary, Components sent, the Carbon ledger and Technical details (credit batch codes four times, the same automatic figures three times) and its ledger table scrolled sideways at 390 px → a totals row (Estimated CO₂e stored with the one ⓘ, Biochar dry mass, Reporting window, Files to upload), a quieter facts row, then one component table (Component, Figure, Source, State) under a header that names each credit batch once with its dates, dry t and production claim. Source records and Technical details are closed disclosures. The blocker Notice names each blocked component with its credit batch; each name scrolls the table to that row and focuses it. Blocked, Sent earlier and Included read differently: a blocked row stays white (only the Notice is tinted) and carries the warning icon, "Blocked", what to do and the link; "Sent earlier" means an earlier Removal holds the batches' production emissions claim, so a production component is left out (the batch header links that Removal; the row does not); a component left out for any other reason, such as an entry held by another Removal that may still be in progress, reads "In another Removal", never "Sent earlier"; a component can carry several blockers, each with its batch and fix; "Included" is quiet and hidden on a phone, and while the compile runs the figures and totals show the shared skeleton, not "Not yet computed". A blocked or failed compile arrives from the server as an empty review, so the rows still come from the context's lines: blocked components show in full with their fix links, every other row keeps its source and files but shows no figure and no state word, since nothing is verified. The batch header always shows, with each batch's dry tonnes only when there are two or more. A sent component with no figure leaves the figure out, or says why when the code knows (a transport with no legs). Rejected: a "Not available" token (off-vocabulary), a tinted blocked row, per-batch blocks (B, needs a per-batch split the compile does not have) and a summary-first page that hides the figures (C). The Storage sites link moved into the Source records disclosure, and the "Traced back to" counts became its summary line.

- **Returned Removal** (PR #1335 follow-up; 2026-10-21, Kenji picked variant A "Status and notice"): #1134 showed "Correction needed" with a reason line and an action in every list row, on a lock alone → once Isometric returns a GHG Statement the Removal's status reads "Correction needed" (nothing sent changed yet) or "Resubmit needed" (a sent fact changed), pending tone, one line, nothing under it. The sheet carries one Notice: warning with no title naming what changed and where, plus "Resubmit Removal" (opens the New Removal wizard on it); or info "Returned by Isometric" with "Open GHG Statement". The credit batch page lists one open item per returned Removal that includes the batch, and an entry re-entered for it reads "Waiting for resubmit". #1134's "Correction needed" stays where a Removal has no correction data. Rejected: a Next step column with a "Changed since sent" list (B) and a three-step correction tracker (C). Why: the status already says the next step, so a second line, column or tracker said it twice. The first state first read "Returned"; Kenji found it unclear the same day, so it reuses "Correction needed", the label the list already showed.
- **Phone step rail** (#1275 review; 2026-10-21, Kenji): the full numbered rail, scrolled sideways → current step only below 640 px (number, label, "Step 2 of 3"), for New Removal and both GHG Statement dialogs and the Removal template setup. Desktop keeps the full bar.
- **One Removal template, set in two steps** (#1337; 2026-10-21, Kenji picked the rendered mocks): a facility had a "default" template, credit batches pinned it at creation, and each batch had its own Switch template dialog; the setup dialog also carried a Make-default checkbox, a set-on-batches checkbox, an overrides list of what noma decided, and a third Apply step. Operators asked which of the two to touch. → one Removal template per facility and nothing called "default". The dialog is always titled "Set Removal template" and has two steps, Template and Check. Template: a vertical list of radio cards (name, "15 components. Nothing to decide." or "N to decide"; templates that cannot be used are disabled with "Not ready" and their reason). Check: the questions noma cannot answer first, then Removal template now to After, then one line naming the credit batches that switch and those that keep their template (Removal sent, certified; archived ones are left out), then the emissions-entry caption. Footer: Set template (busy "Setting template…"), Back, Cancel. Set template switches every credit batch whose Removal is not sent. The credit batch page shows its template read-only with a "Change in Settings" link; the per-batch switch dialog and the "Decide components" link there are gone. Why: one place changes the template, so the answer to "which template does this batch use" is never a batch-by-batch choice, and the dialog ends on the consequence (what switches) instead of on options. Rejected: keeping a per-batch switch for exceptions (sent batches are protected by the server instead), a Make-default toggle, a folded list of what noma decided.

## Certification lists

- **Submitted on and Last synced** (#1105, #1281; 2026-10-20): the Removals and GHG Statements lists showed only a status, so a statement waiting for weeks looked like one sent today → "Submitted on" on both lists and "Last synced" on GHG Statements, each hideable with Columns, one line, sortable by date with undated rows last in both directions, and still searchable by the shown text. Removals date from the ledger submit. Statements date from the verifier submission (`submittedToVerifierAt`, the latest resubmission wins), not from the ledger row, which is stamped when the registry draft is created. Labels: "Not submitted" (no submission yet), "Submitted in Isometric" (past draft in the registry with no recorded date, whoever created it), "Never" (not synced). "Last synced" is the latest successful registry sync, recorded as one `ghg_statement:sync` event per statement; those events are left out of the submission history so they cannot push failed submits out of its window. Rejected: showing the ledger `submitted_at` for statements, and "Not available" for missing dates.
- **Switching organization asks first; deletes finish on the list** (#1364; 2026-10-22, Kenji picked A on both): with an unsaved Settings pane, picking another organization moved the server session and then the browser's "Leave site?" fired, and Stay left the page in the old organization with the sidebar stuck on "Switching…". A delete that returned to a list toasted first and navigated second, so for seconds the page sat still with nothing busy. → The switcher asks with the shared discard dialog ("This section has changes that are not saved. Switching organization discards them.") before it calls the server; Keep editing changes nothing, Discard changes switches without a second browser prompt, a clean pane switches at once, a save in flight ignores the pick. The picked organization carries the spinner and the rest are disabled; a failed switch names the organization. Delete dialogs show the `busy` spinner on the confirm button instead of "Deleting..." and stay open until the list has rendered, and the success toast arrives with the list (`useNavigateWithToast`, rule under Button in `docs/design-system.md`). Why: the answer is asked while it can still be "no", and something on screen is always busy until the result shows. Rejected: letting the browser prompt do the asking, clearing the dialog first and toasting on the list afterwards without a busy dialog, a text swap beside the spinner.
