# Issue or walkthrough update

Use the relevant sections; omit empty sections for a simple concern. For an
existing issue, add a dated update or carefully refresh the body while retaining
prior decisions, comments, acceptance criteria, and evidence links. Read the
latest issue again before editing to avoid overwriting intervening updates.

- **Problem and impact:** user task, concern in the user's terms, actual versus
  desired outcome; distinguish observed behavior from suspected cause.
- **Reproduction/context:** environment/version, route, role, data state,
  viewport, and numbered steps; indicate original capture or reconstructed replay.
- **Visual evidence:** numbered, captioned images/storyboard using verified
  durable URLs; identify gaps and publication blockers explicitly.
- **Direction:** problem only, pending proposal(s), selected option with decision
  source, or designer handoff. Embed proposal images labeled concept/prototype;
  keep rejected/superseded directions traceable.
- **Scope and acceptance criteria:** observable behavior and relevant states;
  separate agreed criteria from tentative suggestions and out-of-scope work.
- **Open decisions:** question, who needs to resolve it if known, and whether it
  blocks implementation. For designers, include constraints and the desired
  decision/deliverable; avoid inventing an assignee or a deadline.
- **Links:** related issues, existing discussion, design/prototype reference,
  and implementing PR when present.

Maintain observation-to-issue mapping in the session ledger. Board Status and
Priority remain project fields; mention verified state in the handoff summary
rather than maintaining duplicate status labels. A later walkthrough should
say what new evidence changes, what still holds, and what remains undecided.
